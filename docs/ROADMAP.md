# Hana Reader 后续路线

当前版本：`v1.3.0`（本地分支 `feat/reader-visual-simplification`）

本路线只记录真实边界和下一阶段工作。所有后续能力都必须保持本地优先、ResourceIO 安全边界和清爽的 Hana 蓝视觉体系。

## v1.2.0 已完成：视觉与交互收束

### 工作区

- 左侧文件树移除前端搜索、最近打开和多余说明，仅保留选择、刷新、打开目录和折叠。
- 文件夹使用黄色闭合 / 展开图标，常见文件类型使用轻量图标。
- 中间栏自适应宽度，阅读与编辑控件改为悬浮控件，左右留白统一。
- 标题收束为 h1 / h2 使用蓝色，h3-h6 使用正文色；代码和引用保留统一的明亮 Hana 蓝。
- 右侧只保留 AI 辅助 / 笔记本切换。

### 阅读、编辑与批注

- Markdown / 代码阅读、Milkdown 编辑、自动保存、冲突保护、安全 HTML 预览保持可用。
- 编辑态 `Ctrl/Cmd + Z` 交给原生编辑器；只读态按时间撤销最近一次批注或最近一次安全写回。
- 批注侧栏移除，选区操作改为正文下方悬浮菜单。
- 批注使用正文橙色波浪下划线与悬浮气泡；高亮、下划线和文本锚点恢复保持。
- 通过 `resource.open` 的 `mode: reveal` 打开当前目录的本地文件资源管理器。

### AI 与 Notebook

- AI 默认读取当前打开的文本文件，不再显示预设、上下文长度或选区上下文配置。
- Notebook 收束为选择、新建、改名、直接编辑和 Markdown 导出。
- 批注、Notebook、会话位置和 Copilot 历史仍只保存在当前浏览器本地。

## 已完成基础能力

### 阅读与编辑

- 选择本地文件夹并延迟展开目录树。
- 阅读 Markdown、JSON、HTML、JavaScript、TypeScript、Python 等文本文件。
- Markdown 安全渲染、GFM 表格、任务列表、代码高亮和安全 HTML 预览。
- 本地 Milkdown Markdown 所见即所得编辑器与多类型源码编辑器。
- 多类型文本安全写回、版本冲突检测、自动保存失败处理和最近一次写回撤销。
- 单文件 2 MB 读取上限、编辑内容 512 KB 上限。

### AI Copilot

- 通过插件 route 调用 Hana `model:sample-text`。
- 当前文件与对话历史按受限字段提交，模型不可用时本地阅读、编辑和 Notebook 仍可用。
- 支持直接提问、失败重试和按文件保存对话历史。

### 受限服务端搜索

- `POST /resources/search` 仍保留递归文本扫描能力，供未来重新接入受控搜索体验。
- 服务端边界：最多 500 个文件、单文件 1 MB、总读取 8 MB、最多 100 个结果。
- 本轮不在前端提供搜索入口，也不做常驻索引。

## 下一阶段：优先级

1. **批注导入 / 导出**：继续使用 sidecar 或本地 JSON，不改变原始 Markdown。
2. **Notebook 本地数据维护**：完整 JSON 导出、导入预览、存储损坏恢复和清理入口。
3. **轻量阅读历史**：多标签或固定阅读项，复用当前单编辑器生命周期，不引入多 Milkdown 实例。
4. **长文档体验**：代码分段渲染、Markdown 分段处理，先建立基准文件和 Chromium 性能回归。
5. **仓库维护**：清理死 CSS，补充构建产物体积与依赖审计，始终排除 `knob-motion-lab/`。
6. **搜索重新接入**：只有在确定交互入口和用户需求后复用现有 route，不重复实现后台索引。

## 需要 Hana 宿主或协议设计的能力

- 跨文件问答：需要明确检索范围、模型授权和上下文计费边界。
- Git 状态与 Diff：需要稳定的宿主读取或执行能力，浏览器不能直接访问本地 `.git`。
- 批注跨设备同步：需要 ResourceIO sidecar 或专门的审阅文件格式，并定义版本、冲突和隐私边界。
- Notebook 创建新文件：取决于宿主是否提供安全的资源创建 API。
- 更完整的 `resource.open` 语义：需由 Hana 宿主决定 reveal / open / external 等模式和平台兼容行为。

## 不纳入插件范围

`knob-motion-lab/` 是其他对话正在开发的旋钮实验目录。本插件不依赖它，也不应把它加入 Reader 的提交、安装包或测试范围。

## 兼容与安全边界

- 浏览器不直接读取本地路径，用户资源继续通过 `ctx.resources` / ResourceIO 路由访问。
- 写回必须携带读取时的 `version` 和 SHA-256，不接受无基线覆盖。
- Copilot route 对文件、选区、历史条数和长度做服务端限制。
- 批注和 Notebook 默认保存在浏览器本地，不提交 API Key、Cookie、个人文件、会话导出或真实项目内容。
- 每次发布前运行 `npm test`，确认版本、构建产物、路由和静态结构回归全部通过。
