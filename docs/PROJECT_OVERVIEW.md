# Hana Reader 项目总览

> 项目地址：<https://github.com/2007-bao/hana-reader>  
> 当前版本：`v2.0.0`  
> 当前分支：`feat/reader-visual-simplification`

## 1. 为什么叫“阅界”

“阅界”首先来自它最自然的功能：文件阅览与编辑器，帮助用户在一个清晰的界面里阅读、理解、记录和修改内容。

但“阅”也谐音于“悦”。这是项目最重要的设计理念：**好的插件与技术，审美和美观始终应该放在第一位。** 市面上有许多类似产品，功能五花八门、品类不断增加，却不一定真正做到让用户使用顺手、只保留核心能力、配色协调耐看。

因此，做“阅界”的第一要义不是不断堆叠功能，而是把每一个必要功能做得清楚、克制、顺手，让使用过程本身成为一种愉悦的体验。三栏结构、低饱和配色、插画、动效和细节间距，最终都服务于同一个目标：让阅读工作台既可靠，也让人愿意长时间使用。

## 2. 项目是什么

Hana Reader（阅界）是一个面向 AI / 多 Agent 产物审阅的本地优先阅读工作台。它把文件浏览、内容阅读、Markdown 编辑、正文批注、AI 辅助与个人笔记收束在一个轻量的三栏界面中。

核心理念是：**先让阅读舒服，再让理解顺畅，最后让记录和修改自然发生。** AI 是辅助能力，而不是替代阅读的主界面。

## 3. 这片海，也是一点小小的玩心

我们专门考虑了“冲浪模式”：收起左右两个侧边栏，专注于当下的文件。此时你就像一艘快艇，在海面上飞速翱翔；也祝你的效率像奔涌的浪花一样，一路疾驰。

第一次打开一个空文件夹时，中间的小女孩仿佛正伸手迎接你去点击，带你快速进入工作状态。我们把进入按钮藏在了那只蓝色蝴蝶上，也正是想营造一种“发现入口、轻轻启程”的感觉。

这些插画和动效不是为了装饰而装饰。它们让一个本来偏工具化的文件工作台多一点呼吸、多一点探索感，同时仍然保持安静，不打扰真正的阅读。

## 4. 当前能力

### 三栏阅读工作区

- 左侧文件树：选择文件夹、延迟展开目录、刷新和打开本地目录。
- 中间阅读区：Markdown 安全渲染、GFM、代码高亮、HTML 安全预览。
- 右侧工具栏：AI 辅助与单一 Notebook。
- 面板支持宽度调整、折叠与状态恢复。

### 阅读与编辑

- Markdown 使用本地 Milkdown 所见即所得编辑器。
- 其他文本与代码使用源码编辑器。
- 自动保存、撤销、版本冲突检测和安全写回。
- 编辑上限、读取上限和二进制识别均在本地 / 服务端边界内处理。

### 正文批注

- 在正文选区下方直接添加高亮、划线或擦除标记。
- 批注使用稳定文本锚点保存在浏览器本地，不改写原始 Markdown。
- 只读模式下支持按时间撤销最近批注或写回操作。

### AI Copilot

- 通过 Hana `model:sample-text` 请求文本模型。
- 默认只提交当前文件、明确选区和当前对话历史。
- 支持 Enter 发送、Shift + Enter 换行、失败重试和按文件保存历史。
- 模型不可用时，阅读、编辑和 Notebook 仍可独立工作。

### Notebook v2.0.0

- 只保留一个 Notebook，移除新建、删除和 Notebook 切换入口。
- 顶部为笔记名称与“导出”按钮。
- 下方为记笔记插画与带半透明笔记本背景的编辑区。
- 笔记内容保存在浏览器本地，导出通过 ResourceIO 安全覆盖已有文本文件。

## 5. 三天开发历程

项目从基础阅读能力开始，逐步经过安全边界、编辑器、视觉系统和交互细节的连续收束。Git 历史保留了每个阶段的真实提交，远端分支与标签用于追溯关键节点。

### 阶段一：基础阅读与安全边界（v0.1.x—v0.6.x）

- 建立插件页面、文件夹浏览和文本阅读基础。
- 接入本地 Markdown 渲染、代码高亮和 HTML 预览。
- 增加 ResourceIO 读取、写回、版本校验与受限搜索。
- 逐步完善错误处理、资源边界和安全预览。

### 阶段二：Maple 视觉与三栏工作台（v0.7.x—v1.4.x）

- 复用 Maple 字体与视觉资源，建立统一的语义色彩系统。
- 完成三栏布局、可调整宽度、文件类型图标和阅读密度优化。
- 加入 Milkdown 编辑器、自动保存、冲突提示和撤销路径。
- 将 Notebook、AI 辅助和正文批注纳入同一阅读工作流。

### 阶段三：插画化阅读体验（v1.5.x—v1.6.x）

- 引入透明阅读插画、AI 空状态和折叠侧栏浪花。
- 集成只读 / 编辑 Quiet 原生旋钮。
- 经过多轮尺寸、留白、镜像、裁切和动效调整，形成更稳定的折叠构图。

### 阶段四：细节收束与 Quiet Motion（v1.7.x—v1.8.x）

- 统一侧栏折叠图标、顶部占位、控件圆角和清爽蓝色体系。
- 稳定宿主高度测量，减少切换和重绘造成的跳动。
- 将文件树、正文、右栏和 Notebook 的变化整理为克制、可中断、支持 reduced-motion 的过渡。

### 阶段五：整体收束（v2.0.0）

- Notebook 从多笔记本管理收束为单一笔记本工作台。
- 形成“名称 / 导出—插画—笔记内容”的清晰纵向结构。
- 完成版本元数据统一、测试维护、项目文档整理和发布包生成。

## 6. 技术结构

```text
manifest.json        插件声明、页面入口与宿主能力
package.json         构建、依赖与测试脚本
routes/ui.js         Page shell、ResourceIO 读写/搜索、Copilot route
src/panel.js         页面状态、三栏布局、阅读、编辑、批注、AI、Notebook
src/*-engine.js      Markdown / 编辑器 / 批注等独立实现
src/notebook-store.js Notebook 本地存储与迁移
assets/panel.js      构建后的前端 bundle
assets/panel.css     页面布局、主题、动效与控件样式
assets/notebook-*.png Notebook 插画资源
docs/                项目总览、路线、交接和技术记录
tests/               版本、结构、渲染、编辑器、路由与存储回归
release-archives/    历史版本安装包归档
```

## 7. 数据与安全边界

- 浏览器不直接读取本地路径，用户文件统一通过 Hana ResourceIO 访问。
- 写回必须携带读取时的版本信息与 SHA-256 内容基线。
- 版本冲突时不自动覆盖远端文件，并保留本地草稿处理路径。
- Markdown 原始 HTML 默认按文本处理；HTML 预览使用 sandbox 与净化。
- 批注、Notebook、会话位置和 Copilot 历史默认只保存在当前浏览器。
- 仓库不提交 API Key、Cookie、会话导出、真实项目内容或个人文件。

## 8. 开发与验证

```powershell
npm install
npm test
```

`npm test` 会依次执行版本一致性检查、esbuild 构建和顺序测试。发布前应确认：

1. `manifest.json`、`package.json`、`package-lock.json`、`src/panel.js` 与 `routes/ui.js` 版本一致；
2. Notebook 插画资源存在且被构建产物引用；
3. 全部测试通过；
4. 发布压缩包只包含插件运行所需的 manifest、源码、路由和 assets；
5. GitHub 主分支、版本标签与发布包可相互追溯。

## 9. 版本与仓库管理

- `main`：稳定可用版本。
- `feat/*`：阶段性开发分支。
- `release/*`：历史发布节点分支。
- `v*`：可回溯版本标签。
- `release-archives/`：历史版本安装包归档，不参与运行时构建。

当前发布节点：

| 版本 | 定位 |
| --- | --- |
| `v0.1.0`—`v0.6.1` | 基础阅读、安全边界与编辑能力 |
| `v0.7.0`—`v0.9.0` | Maple 视觉系统与三栏工作台 |
| `v1.0.0`—`v1.4.4` | 编辑、批注、AI、Notebook 与交互细节 |
| `v1.5.0`—`v1.6.1` | 插画、旋钮与折叠浪花构图 |
| `v1.7.0`—`v1.8.1` | 视觉和 Quiet Motion 收束 |
| `v2.0.0` | 单 Notebook 工作台与整体项目收束 |

## 10. 项目现状

Hana Reader 已从一次性页面原型成长为具有真实文件边界、编辑保护、可回溯版本和完整视觉语言的本地优先阅读插件。当前重点不是继续堆叠功能，而是保持结构稳定、视觉克制、数据安全和可维护的发布节奏。

后续若继续开发，建议优先考虑 Notebook 导入导出、长文档性能、跨设备 sidecar 同步和死 CSS 清理；任何新能力都应先证明不会破坏阅读主线。
