# Hana Reader 后续路线

当前版本：`v1.1.0`（本地开发分支 `feat/offline-search-and-polish`）

本路线只记录真实边界和下一阶段工作，已经完成的能力不再重复列为待办。所有离线能力都必须保持 Maple 蓝色视觉体系、本地优先和 ResourceIO 安全边界。

## v1.1.0 已完成

### 1. 全文搜索

- `POST /resources/search` 在当前已选择文件夹内递归扫描文本文件
- 支持大小写敏感选项、相对路径、行号、列号、预览片段和结果高亮
- 搜索结果可直接打开文件，并定位代码行或 Markdown 的近似行位置
- 服务端边界：最多 500 个文件、单文件 1 MB、总读取 8 MB、最多 100 个结果
- 二进制文件、过大文件和无法读取的文件不会阻塞整个搜索流程
- 搜索不是默认后台索引，只有用户主动提交关键词时才读取当前文件夹

### 2. 最近打开与工作区返回

- 最近打开文件按根资源 + 相对路径保存到浏览器本地
- 当前工作区内可直接回到最近文件；来自其他工作区的记录会明确提示先选择对应文件夹
- 可一键清除最近打开记录
- 不保存个人文件内容、Cookie、模型上下文或会话导出

### 3. 键盘和无障碍维护

- `Ctrl/Cmd + Shift + F` 打开全文搜索
- `Escape` 关闭搜索、取消建议或清除当前选择
- `Ctrl/Cmd + S` 在编辑态触发安全保存
- 文件树补充 `treeitem`、展开状态和当前项语义
- Copilot / 批注 / Notebook 切换补充 tab 语义
- 搜索表单、结果列表、状态提示和可见焦点样式完善

### 4. 验证与维护

- 搜索 route 覆盖目录递归、行列定位、大小写、二进制跳过和空查询
- 版本同步到 `manifest.json`、`package*.json`、前端 ready payload、缓存修订号和 manifest 回归测试
- `npm test` 作为唯一发布前验证入口：先做版本一致性检查和构建，再顺序执行全部测试
- 阅读滚动位置写回 localStorage 使用短暂节流，避免滚轮事件频繁阻塞主线程

## 已完成基础能力

### 阅读与编辑

- 选择本地文件夹并延迟展开目录树
- 阅读 Markdown、JSON、HTML、JavaScript、TypeScript、Python 等文本文件
- Markdown 安全渲染、GFM 表格、任务列表和链接
- 本地 Milkdown Markdown 编辑器
- 多类型文本安全写回
- 版本冲突检测、自动保存失败退出、撤销和安全 HTML 预览
- 单文件 2 MB 读取上限、编辑内容 512 KB 上限

### AI Copilot

- 通过插件 route 调用 Hana 的 `model:sample-text` 能力
- 用户明确勾选当前文件或选中文本后才发送上下文，不默认读取整个项目
- 总结、解释、知识点提取和 Markdown 审阅快捷任务
- 按文件保存对话历史，支持失败重试和上下文长度控制
- 修改建议必须经过原文匹配、预览确认后才应用回 Markdown

运行前提：Hana 版本需要提供 `model.sample` / `model:sample-text`，且已配置可用的 utility 文本模型。模型不可用时，Reader 的本地阅读、编辑、搜索、批注和 Notebook 仍可用。

### Markdown 批注与审阅

- 选中文本后添加批注、高亮或下划线
- 批注支持回复、编辑、删除、完成/重新打开和最近一次操作撤销
- 批注侧栏支持定位原文，并使用文本锚点在重新打开后恢复
- 按状态/类型筛选批注，并可对当前筛选结果批量完成
- 批注存于本机浏览器，不向普通 Markdown 注入私有语法

### Notebook

- 多份 Notebook、标题编辑、切换、新建和删除
- 引用当前文件或选中文本
- 从批注或 Copilot 回复一键生成笔记
- Markdown 预览、下载导出和带版本校验的安全写回
- 内容独立于当前文件，使用浏览器本地存储自动保存

## 下一阶段：仍可全线下推进

按收益和回归风险排序：

1. **最近文件进一步完善**：工作区切换入口、按根目录分组、恢复失败记录的删除。
2. **搜索体验增强**：文件名过滤、结果排序、多次命中展开和搜索历史清理；继续保持服务端总量边界，不做常驻索引。
3. **批注管理**：批量删除前确认；增加批注导出/导入，不改变原始 Markdown。
4. **Notebook 本地数据维护**：导出完整 Notebook JSON、导入前预览、存储损坏时的恢复提示和清理入口。
5. **阅读工作流**：轻量多标签或“固定阅读项”视图。先复用现有当前文件状态，不引入多编辑器实例，避免 Milkdown 生命周期复杂化。
6. **长文档体验**：代码行分块渲染、Markdown 大文档的分段处理、搜索结果按需打开；必须先用基准文件验证再引入虚拟化。
7. **仓库维护**：清理历史死 CSS、补充构建产物体积/依赖审计和 Chromium 性能回归，始终排除 `knob-motion-lab/`。

## 需要 Hana 宿主或协议设计的能力

- 跨文件问答：需要明确的检索范围、模型授权和上下文计费边界；当前可先复用全文搜索结果，但不应自动把整个项目交给模型。
- Git 状态与 Diff：需要稳定读取 `.git` 语义或宿主执行能力，不能在浏览器直接访问本地路径。
- 批注跨设备同步：需要 ResourceIO sidecar 或专门的审阅文件格式，需先定义版本、冲突和隐私边界。
- Notebook 创建新文件：当前只安全写回用户选择的已有文件，创建能力取决于宿主资源 API。
- 实际 Hana UI reload 和模型返回形状：需要 dev loop 可访问工作区路径后再做宿主冒烟，不把宿主路径或 API Key 写入仓库。

## 不纳入插件范围

工作台下的 `knob-motion-lab/` 是其他对话正在开发的旋钮实验目录。本仓库主插件不依赖它，也不应把它加入 Hana Reader 的提交、安装包或测试范围。

## 兼容与安全边界

- 浏览器不直接读取本地路径，用户资源继续通过服务端 `ctx.resources` / ResourceIO 路由访问。
- 搜索只在用户主动提交关键词后运行，服务端固定限制文件数、单文件大小、总读取量和结果数。
- Copilot 上下文只接受前端明确提交的文件或选区，并在 route 层做字段、条数和长度限制。
- AI 建议应用前需要精确匹配当前 Markdown 原文；无法定位时不会自动覆盖。
- Notebook 写回必须带读取时的 `version` 和 SHA-256，不接受无基线覆盖。
- 批注、Notebook、最近文件和 Copilot 历史仅保存在本机浏览器，不提交 API Key、Cookie、个人文件、会话导出或真实项目内容。
