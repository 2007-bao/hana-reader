# Hana Reader 后续路线

当前版本：`v1.0.0`（本地开发分支 `feat/complete-reader-workbench`）

本次已把 v0.9.0 交接文档中列出的三项核心能力完成：Copilot、Markdown 批注审阅、Notebook 增强。下面只保留下一阶段的候选能力与明确限制，避免新对话把已完成内容当成待办。

## v1.0.0 已完成

### 1. AI Copilot

- 通过插件 route 调用 Hana 的 `model:sample-text` 能力
- 用户明确勾选当前文件或选中文本后才发送上下文，不默认读取整个项目
- 总结、解释、知识点提取和 Markdown 审阅快捷任务
- Copilot 对话历史按文件保存在本机，并限制历史条数
- 失败提示与重试
- 上下文长度档位（8k / 16k / 24k），服务端再次截断保护
- AI 修改建议必须使用 Markdown 代码块返回，并经过原文匹配、预览确认后才进入编辑器和安全自动保存

运行前提：Hana 版本需要提供 `model.sample` / `model:sample-text`，且已配置可用的 utility 文本模型。模型不可用时，Reader 的本地阅读、编辑、批注和 Notebook 仍可用。

### 2. Markdown 批注与审阅

- 在 Markdown 阅读视图中选中文本后添加批注、高亮或下划线
- 批注支持编辑、回复、完成/重新打开和删除
- 批注侧栏、定位原文和当前原文是否仍可定位的状态提示
- 通过文本引用、前后文锚点恢复标记，重新打开同一文件后仍可见
- 最近一次批注操作可撤销
- 批注保存在浏览器本地存储，原始 Markdown 不被注入 HTML 注释或私有语法，保持普通文件兼容

明确边界：批注目前是“本机阅读审阅层”，不会随 Markdown 文件自动同步到其他设备。若需要协作同步，下一阶段应设计 ResourceIO sidecar 或专门的审阅文件格式。

### 3. Notebook 增强

- 多份 Notebook、切换、新建、删除和标题编辑
- 从当前文件或选中文本建立 Markdown 引用
- 从批注或 Copilot 回复一键加入 Notebook
- Notebook Markdown 预览
- 下载为 Markdown 文件
- 选择已有文件后，通过 `version + SHA-256` 安全写回
- 本机自动保存，不影响被阅读文件

## 下一阶段候选能力

这些内容不是 v1.0.0 的核心验收项，按产品优先级另行安排：

- 全文搜索与结果定位
- 跨文件问答（仍需显式选择文件范围）
- Git 状态与变更概览
- 多标签、最近打开文件和跨文件阅读历史
- 批注筛选、批量完成和 sidecar 协作同步
- 更完整的 Diff / 审阅合并工作流
- 深色模式细化、键盘操作、可访问性和长文档性能优化

## 不纳入插件范围

工作台下的 `knob-motion-lab/` 是其他对话正在开发的旋钮实验目录。本仓库主插件不依赖它，也不应把它加入 Hana Reader 的提交、安装包或测试范围。

## 兼容与安全边界

- 浏览器不直接读取本地路径，用户资源继续通过服务端 `ctx.resources` / ResourceIO 路由访问。
- Copilot 上下文只接受前端明确提交的文件或选区，并在 route 层做字段、条数和长度限制。
- AI 建议应用前需要精确匹配当前 Markdown 原文；无法定位时不会自动覆盖。
- Notebook 写回必须带读取时的 `version` 和 SHA-256，不接受无基线覆盖。
- 不提交 API Key、Cookie、个人文件、会话导出或真实项目内容。
